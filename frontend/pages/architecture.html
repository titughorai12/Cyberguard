System architecture & evaluation

What CyberGuard analyzes, how findings are scored, and which capabilities remain prototype-only.

Detection to response, with evidence

CyberGuard combines deterministic rules with optional Gemini assessments. Each completed analysis returns a category, risk score, explanation, evidence, and a recommended next step. The system recommends response actions; it does not automatically block users, URLs, or accounts.

Data flow

Analysis requests are handled by FastAPI routes, assessed by the relevant detector, normalized into risk results, optionally saved, and displayed in the SOC dashboard.

1 · SubmitURL, message text, decoded QR content, image, or authorized sample login events
2 · DetectRules plus optional Gemini text or visual assessment
3 · ExplainRisk category, score, indicators, confidence when available, and safe next steps
4 · RecordURL findings and supported security events stored in the configured database
5 · RespondAnalyst reviews findings and follows recommended containment or verification guidance

Risk scoring

  • URL rules add bounded weights for HTTP, IP hosts, deep subdomains, auth-related host keywords, selected TLDs, user-info syntax, long URLs, shorteners, and punycode.
  • When Gemini is configured, the URL hybrid score is the greater of the rule score and a weighted AI/rule score (65% AI, 35% rules).
  • Message rules use risk thresholds; login anomaly rules score the supplied sample; image scores are returned only after visual AI screening.
  • Scores and thresholds are prototype heuristics, not calibrated probabilities.

Models and services

  • Gemini model configured by GEMINI_MODEL provides optional text analysis and general-purpose visual review.
  • Python URL and QR classifiers use transparent pattern rules; authentication analysis uses behavioral rules over the submitted events.
  • SQLAlchemy persistence stores URL analyses and normalized security events when the database is available.
  • Missing Gemini configuration falls back to rules or explicitly marks visual review unavailable.

Privacy and trust boundaries

  • Do not submit real credentials, OTPs, API keys, or private identity data.
  • For image AI screening, pixels are sent to the configured Gemini provider; this prototype does not store uploaded pixels.
  • Message analysis evaluates text only and does not open links or verify senders.
  • Login analysis uses only the authorized sample submitted by the analyst.

Deployment shape

  • Frontend: static HTML/CSS/JavaScript served by FastAPI.
  • API: FastAPI routes under /api/v1, with Pydantic request validation.
  • Storage: configured PostgreSQL database via SQLAlchemy; database degradation is surfaced in health status.
  • Scale path: deploy behind TLS and an API gateway, use managed secrets, add queue-based analysis and approved threat-intelligence/identity integrations, and retain evidence under a documented policy.

Evaluation status

The repository does not contain a labeled, independently verified benchmark or measured accuracy results. Do not report an accuracy percentage until an evaluation has been run.

Recommended evaluation: build a labeled, deduplicated test set for phishing URLs, benign URLs, scam/benign messages, QR destinations, authorized login anomalies, and manipulated/authentic images. Freeze the set before tuning. Report per-scenario precision, recall, F1, confusion matrix, false-positive rate, latency, model/config version, and sample count. For image screening, have multiple reviewers label the cases and measure reviewer agreement.
